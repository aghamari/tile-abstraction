The problem. One MFMA writes a 16×16 tile of C, the f32 accumulator: 16 rows of M by 16 columns of N, 256 values.

HIP load and store · load_C_16x16_col_major

mfma_debug/01_simple_hgemm.cpp. C is column-major, ldc = m. The launch is gemm_test(16, 16, 32), so ldc = 16. The tile is load_C_16x16_col_major(c + (cRow + cCol·ldc), ldc) with cRow = 0 and cCol = 0. The store writes the same addresses with store_C_16x16_col_major.

Each lane takes one column of N and four consecutive rows of M. In column-major those four f32 are adjacent, so the load is one global_load_dwordx4 and the store is one global_store_dwordx4.
